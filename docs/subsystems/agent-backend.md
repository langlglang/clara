# Agent and backend handoff

**Demo implemented:** one constrained server turn per final utterance, with a strict per-turn action schema, a phrase guard, and a local Pi fallback line. **Proposed:** a persistent Core Clara conversation with typed tool calls and concurrent background tasks. See [conversation runtime](../conversation-runtime.md) and [contracts](../contracts.md).

The lid event starts a local Pi session and microphone; it does not call the cloud agent. Each final user utterance is an actual request. The current server can return a short reply or select a preauthored scenario panel, ask a prewritten question, locate an item, or request simulated SOS. The Pi renders these as answer, question, guidance, or item cards. It cannot yet produce diagrams or reading cards. A future presenter must add source and measurement references, while the model can only select approved medical content and cannot invent sensor values or a diagnosis.

Core Clara is the sole conversational voice. It stores a short recent-turn window plus a source-labeled session summary. A supervisor launches bounded emergency, responder, evidence, or handoff jobs only from recorded triggers. Workers return status or observations to Core Clara and cannot speak independently or claim delivery. Every observation carries its source and time. Late results from a cancelled turn are ignored. Simulated SOS starts locally without waiting for the agent, camera, sensor, or network.

Acceptance for the proposed runtime: opening the lid makes no model request; a final utterance initiates one turn; a relevant answer, item map, diagram, reading, question, or status can be displayed without a mandatory step sequence; user interruption cancels obsolete speech and visuals; background jobs do not block conversation; a disconnect leaves the last committed visual and mock SOS available; an uncertain frame or stale sensor cannot become a factual claim. Guidance content follows the [fictional demo content check](../medical-safety.md).
